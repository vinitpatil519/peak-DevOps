# Observability

## Signals

| Signal | Source | Store | View |
|---|---|---|---|
| App metrics (RED + business) | FastAPI `/metrics/` via Istio metrics merging (`:15020/stats/prometheus`) | Prometheus | Grafana "Application", "Business" |
| Mesh metrics | Envoy sidecars (`istio_requests_total`, …) | Prometheus | Grafana "Cluster" (mesh row), Application (traffic split) |
| Dependency metrics | postgres-exporter, redis_exporter, apache-exporter sidecars | Prometheus | Grafana "Application" dependencies row |
| Cluster/node | kube-state-metrics, node-exporter, cAdvisor | Prometheus | "Cluster", "Nodes" |
| Logs | stdout JSON (FastAPI, NGINX, Apache, Envoy) → Fluent Bit → Loki | Loki | Grafana Explore, "Application" logs panel |
| Alerts | PrometheusRule `cloudforge-rules` | Alertmanager | chat / pager webhooks |

Correlation: every request carries `X-Request-ID` (generated by Apache if absent, forwarded by
NGINX and Envoy). Grafana's Loki datasource turns `request_id` into a clickable derived field.

## Metrics reference (application)

| Metric | Type | Labels |
|---|---|---|
| `http_requests_total` | counter | method, route (template, low cardinality), status |
| `http_request_duration_seconds` | histogram | method, route |
| `http_requests_in_flight` | gauge | — |
| `cloudforge_cache_events_total` | counter | result = hit, miss, error |
| `cloudforge_orders_created_total` | counter | product |
| `cloudforge_order_revenue_cents_total` | counter | — |

Blueprint coverage: CPU, memory, disk, network (Nodes + Cluster dashboards); request latency,
error rate, throughput (Application dashboard + recording rules).

## Dashboards (dashboards-as-code)

`monitoring/grafana/generate_dashboards.py` → `helm-charts/charts/platform/files/dashboards/*.json`
→ ConfigMaps labelled `grafana_dashboard=1` → Grafana sidecar loads them into folder
"CloudForge". Edit the Python, run `make dashboards`, commit the JSON.

| Dashboard | Highlights |
|---|---|
| CloudForge / Cluster | capacity vs requests, pods not ready, restarts, CPU/mem/net by namespace, HPA vs max, PDB headroom, mesh RPS, mTLS share |
| CloudForge / Nodes | CPU by mode, memory, disk space + IO, network throughput/errors, load per core |
| CloudForge / Application (RED) | throughput, 5xx ratio, p50–p99, per-route breakdown, canary vs stable error ratio, mesh traffic split, cache hit ratio, Postgres/Redis/Apache, Loki errors |
| CloudForge / Business | orders, revenue, AOV, checkout success rate, top products |

## SLOs and alerting

SLO: 99.5 % of API requests succeed (non-5xx) over 30 days; p95 < 500 ms.

Burn-rate alerts (Google SRE workbook multi-window): fast burn 14.4× over 5 m **and** 1 h
(page), slow burn 6× over 1 h **and** 6 h (ticket). Plus dependency, workload and capacity
alerts — see `helm-charts/charts/platform/templates/prometheusrules.yaml` and
[runbooks](runbooks.md).

## Useful queries

```promql
# error ratio by route
sum by (route) (rate(http_requests_total{status=~"5.."}[5m])) / sum by (route) (rate(http_requests_total[5m]))
# canary vs stable
sum by (rollouts_pod_template_hash) (rate(http_requests_total[2m]))
```

```logql
{namespace="backend"} | json | level="ERROR"
{namespace=~"frontend|backend"} |= "3f2c9a"          # follow one request id across tiers
sum by (status) (count_over_time({namespace="ingress-nginx"} | json [5m]))
```
